# История изменений

## 1.1.5

- Исправлено открытие защищённой настройки и регистрации на macOS: worker запускается через вложенный `Orca Helper.app`, но публичный CLI находится в `Contents/Resources/bin/orca` внешнего `Orca.app`. Прежний путь указывал на отсутствующий launcher внутри Helper и приводил к алерту «Не удалось выполнить команду плагина».
- Добавлена регрессия для main/Helper/Renderer executable paths и precedence managed/development CLI. Helper-backed IPC smoke теперь использует тот же resolver, что и плагин; isolated host storage не выдаётся за OS vault.

## 1.1.4

- Добавлен authenticated `/v1/usage?days=7`: баланс аккаунта, лимит и остаток ключа, расходы, запросы и токены сегодня/за весь срок, доступные оконные лимиты. Отсутствующие значения не превращаются в нули; ошибки API не раскрывают ключ или upstream response.
- Эти данные доступны в защищённой странице плагина с временем обновления и кнопкой повторного запроса. Требование живого вывода в native sidebar не выполнено: Orca 1.4.223 запрещает panel сеть и чтение worker/storage, а установленное содержимое проверяется по hash. Orca и её защитные настройки не изменялись.
- Исправлен ложный TOML-конфликт Codex, когда WikiVibe присутствует только в имени project path. Подключение и применение к Codex/OMP/OpenCode проверены через настоящий IPC worker с отдельным реальным ключом; host storage в этой проверке изолирован, не OS vault.
- Свежие OMP/OpenCode прочитали 15/15 моделей. Codex app-server с эквивалентными профильными overrides прочитал 15/15; запуск TUI `codex -p wikivibe` остановился на существующей ошибке `features.multi_agent_v2`, без изменения пользовательской конфигурации. Inference не выполнялся.

## 1.1.3

- Защищённая настройка и команда регистрации открываются во встроенном браузере Orca через публичный CLI, без системного браузера и внешнего fallback. Проверено настоящим IPC worker установленной Orca.
- Поддержан существующий OpenCode `opencode.jsonc`; комментарии вне каталога сохраняются. Существующие OpenCode/OMP WikiVibe каталоги обновляются без замены credentials, endpoint, provider ID и активной модели, с backups и конфликтной защитой.
- Результат применения показывает размер каталога по агентам и явно отличает запись файлов от проверки интерактивного меню.
- Реальные локальные каталоги OMP/OpenCode синхронизированы с authenticated API: 15/15 ID прочитаны установленными CLI/backend без inference. 48/48 поведенческих тестов прошли; уже работающие сессии не прерывались.
- Исправлена сломанная картинка в заголовке панели: присланный логотип встроен в HTML как прозрачный PNG, metadata использует отдельный PNG. Проверено декодирование во встроенном браузере и sandbox `srcDoc`; установленная копия через Settings отдельно не проверялась.
- Кнопка регистрации в защищённой странице также открывает встроенную вкладку; её реальный клик проверен через IPC worker и Orca CLI.

## 1.1.2 — опубликовано

Шаги подключения и кнопка повторной инструкции сохранены; предупреждение перед применением в защищённой настройке не менялось.

## 1.1.1 — опубликовано

- Исправлены неполные списки WikiVibe при существующих фильтрах: Claude `availableModels`, Pi/OMP `enabledModels`, OMP `enabledProviders` и OpenCode `enabled_providers` расширяются только разрешёнными моделями или провайдером WikiVibe.
- Из OMP `disabledProviders` и OpenCode `disabled_providers` удаляется только `wikivibe`; остальные ограничения и активные модели/defaults сохраняются. Неограниченные пустые списки OMP остаются пустыми.
- Pi `settings.json` и OMP `config.yml`/`.yaml` используют те же backups, конфликтную защиту и точное восстановление, что и каталоги. При обновлении исчезают только добавленные плагином устаревшие ID.
- Preview предупреждает об изменении фильтров. Неоднозначные и path-scoped YAML-фильтры не переписываются; managed/project settings остаются вне области плагина.
- Установленные OpenCode и OMP показали все 14 тестовых моделей во временном HOME с исходными ограничениями; inference-запросы не выполнялись.

## 1.1.0 — опубликовано

- Вместо общей ошибки сохранения ключа панель показывает безопасную категорию причины: доступ к API, сеть, лимит запросов, каталог или хранилище Orca. Текст ответа API и ключ не передаются в сообщение ошибки.
- Защищённая настройка подключает провайдера WikiVibe; выбор активной модели перенесён в сам агент. Сохранённый выбор модели больше не используется.
- Каталог определяется только authenticated `/v1/models` для введённого ключа. Все возвращённые модели передаются адаптерам; публичный marketplace больше не участвует в подключении и не расширяет доступ.
- Перед просмотром и применением каталог обновляется, чтобы импортировать актуальные разрешения ключа.
- Нативные каталоги агентов регистрируются без назначения модели по умолчанию. Ограничения выбора провайдера и протокола показаны в preview и инструкции.

## 1.0.1

- В версии 1.0.1 были приведены ссылки на репозиторий и исходники к `https://github.com/taranttoola-create/wikivibe-orca-plugin`. Основной адрес установки был закреплён за тегом версии `v1.0.1`; эта запись сохранена для истории.

## 1.0.0

- Создан самостоятельный плагин `wikivibe.gateway` для Orca plugin API 1. Поддержана обычная установка из локальной папки или Git-источника; отдельный helper не нужен.
- Добавлены регистрация по партнёрской ссылке, разрешённые адреса API/VAPI, проверка каталога до сохранения ключа в зашифрованном хранилище Orca и выбор модели.
- Добавлена защищённая локальная панель с предварительным просмотром, явным согласием, применением, восстановлением и удалением ключа плагина.
- Реализованы семь адаптеров нативной конфигурации: Claude Code, Codex, OpenCode, Pi, oh-my-pi, Aider и Qwen Code. Модели Aider направляются через префикс `openai/` по документации агента.
- Добавлены резервные копии по файлам, права доступа POSIX и отказ от восстановления поверх последующих пользовательских изменений.
- Документированы ограничения протоколов, профилей, удалённых окружений и WSL, открытое хранение ключей в конфигурациях CLI и срок жизни worker. Публикация в marketplace и успешная генерация ответа агентом не заявлены.
